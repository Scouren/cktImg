# Ninth body round: local contracts, candidate poses and committed frames

The current package diagram puts a **complete final world frame** before G,
but G chooses an arrangement and can change each member's origin and pose.
That wording hides a conceptual cycle. Resolve the immutable local contract
first; evaluate a world frame for each complete tentative arrangement; commit
only a validated arrangement. Final coordinates exist only after the last
coordinate writer. This is a proposed boundary, not an implemented resolver.

The other dependency correction is independent: adding every new symbol
family is not a prerequisite for local MOS organization. AG1080 and AG928
already have MOS frames with which to study stage boundaries and one-core
alternatives. Their required per-cohort capability still needs verification;
the seven new amplifier/clock contracts and the rounded digital-gate
overshoot do not block a cohort that does not use those glyphs. A capability
check and implementation of all missing capabilities are different tasks.

For a bounded D/G/S arrangement experiment, an existing three-contact MOS
glyph can retain its current rail-body presentation while all four raw
bindings remain checked. That does not certify an actual B contact or an
explicit caller-hidden request. A candidate that needs a visible B escape
or bridge declines until its selected class supplies that required contact;
an unrelated missing capability must not veto collection or the narrower
arrangement experiment.

## What is fixed, and what is allowed to move

| Boundary | Owned output | Conditions before a consumer uses it |
|---|---|---|
| R/K: verify required capabilities for the admitted cohort | Ordered electrical role bindings; supported local class contacts and own-lead meaning; explicit unknown capabilities | Every raw terminal remains counted. Verify the selected class, not merely its family or a previous variant. Unsupported roles decline the affected candidate. |
| O: collect and resolve ownership | Complete member/attachment/interface references and caller constraints | Raw competitors precede eligibility filters. No coordinates change. Shared nets do not merge owners. |
| P/B: propose occurrence policies | Signed-slot and body routing/presentation requests, with admitted caller authority | Requests are compatible or decline; neither producer mutates a shared class or silently substitutes a terminal's node. |
| C: select the immutable local contract | ClassId, complete ordered contact capabilities, allowed poses, and cold presentation/interface requirements | One compatible selected variant includes all applicable policies. A visible-contact request with no supported own landing declines. |
| G: propose one complete local arrangement | Member origins/poses relative to the parent anchor, plus the parent's anchor proposal | Bounded alternatives; explicit caller poses and group relations constrain the proposal. G owns proposed coordinates. |
| F: evaluate that candidate's world frames | Actual tips, sides, body bounds, own-lead support and required interface/label/escape reservations | F is a read-only evaluator of C and the proposed poses. It cannot choose a different class or quietly move a child. |
| A: validate and commit the complete candidate | Accepted member poses and corresponding reservations, or a precise decline | All members, inter-owner interfaces, collisions, caller relations and required route capabilities pass together. No partial child commit. |
| Later coordinate writers and final validation | Re-evaluated frames at the poses actually used for routing/export | Packing, compaction and admitted caller placement preserve the accepted relations or reject their own proposed move. Stale world contacts/reservations never survive a changed pose. |

This is a finite proposal pipeline, not a G/F fixed-point solver. G enumerates
a named bounded set of alternatives. Each alternative gets scratch frames
and reservations, followed by one validation result. A decline tries the next
alternative or keeps the previous valid layout. The bound comes from the
supported template, member population and allowed poses, not the number of
observed source examples. Fallible preparation and collision checks precede
the commit; an allocation failure leaves the previous state intact.

Global packing need not destroy locality: it can translate a whole admitted
owner while preserving relative member poses. It still has to instantiate
the translated contact/interface frame. If compaction changes distances or
orientation inside that owner, its proposal must recheck the actual retained
relations and all affected clearances. Checking only origins or the old group
box misses the sixth-group mutation that moved just one gate endpoint.

The subsequent independent ports review sharpens the physical-piece
boundary: N can qualify immutable pin partitions and naming obligations
before G; it cannot already prove their realized world contacts. F maps
their reserved interfaces, and W validates their routed realization. A's
route-capability/clearance checks are not route-success proof unless A runs
an explicit scratch routing trial. If later W fails, reject or restore the
complete affected arrangement; do not leave successful children committed.
H must preserve or recompute N's separation and naming reservations as well
as body bounds. These are required failure semantics for the proposed
pipeline, not results of current native execution.

## Body policy and bounds

The current `Class.bbox` includes **all** class terminals and draw primitives;
it does not read `Terminal.hidden`. Therefore toggling only that flag on an
otherwise identical class changes ordinary routing participation (`shows`
and `side`), but leaves contact coordinates and that class's box unchanged.
The sixth native controls also show that a hidden body's glyph lead can
remain visible and can meet another hidden lead. Hidden is not erased ink.

Changing the representation can nevertheless change geometry. A new B
contact or own lead can extend the class box; selecting a signed or body
variant can change contacts without changing the box. A named attachment can
require label clearance outside the body box. A bridge between members can
require an interface corridor without changing either device's box. Keep
these separate reservations; do not pretend they are all a class rectangle.
In particular, current `DrawOp.text` contributes only its anchor to `bbox`,
so that function alone is not a typographic label-clearance certificate.

The missing-terminal origin fallback in `sketch.hiddenPins` and `Placed`
retains a coordinate for an electrical occurrence; it cannot certify an
actual visible body contact. Conversely, the body-only sources' 22 bridges
and AG1236 omission do not authorize overriding an admitted caller-hidden
routing contract. The older-host target proof now supports the existing
named-body mechanism for three literal cases; it does not equate that
plugin module with the frozen native custom-class experiment.

## Concrete dependency edits suggested to the parent plan

Replace the opening universal `R → S → P/B` implication with a per-cohort K
gate: **verify the capabilities required by this candidate**. Existing
classes can satisfy K immediately after their required proof; S supplies K
only for cohorts needing its newly implemented families or repaired geometry.
T is similarly required at the native/plugin boundary that the experiment
actually exercises. A native prototype may proceed without declaring the
plugin finish line complete. Neither boundary may silently borrow authority
from an opaque generated name or unsupported caller class.

Replace `P → F`, `B → F`, `F → G` with `P/B/K → C`, `O/C → G`,
`G/C → F`, then `F → A`. Describe F as **evaluate the candidate's world
frames**, not **resolve complete final frames before group arrangement**.
For a literal acyclic diagram, draw later packing/compaction and final frame
validation as separate nodes. They use the same evaluation operation at each
coordinate-owner boundary; they do not imply an edge back to earlier G.
X consumes actual admitted stubs from the current frame, after any relevant
pose movement, and still requires its own diagonal capability when chosen.

In package P's closing paragraph, replace “caller/world pose” with “allowed
poses and admitted caller constraints” at C. State that G supplies tentative
poses to F and that every geometry-dependent reservation is based on the
same evaluated candidate. In B, “resolve before geometry consumers” means
resolve the occurrence policy and compatible local capability first; the
world contact then follows the selected pose. This does not promise current
shared capability that the code has not implemented.

Rename S to “Complete additional symbol contracts for cohorts that need
them.” Replace the introductory priority claim with an explicit first
organization experiment: collect complete local candidates without changing
geometry, retain AG928 as a one-core/same-facing control, and attempt one
bounded admitted stage arrangement for the AG1080/global-core problem.
Resolve its actual caller-axis and ownership obligations before movement.
The newer glyph, side-default and rounded-gate repairs can proceed as
independent bounded work. Do not postpone all group collection or MOS
placement research until every unrelated symbol family is complete.

## Literal positive and decline fixtures

The accompanying [machine-readable literals](ninth-frame-fixtures.json)
are prospective contract fixtures, not execution of a nonexistent shared
C/G/F implementation. Expected integer coordinates are written independently
of a frame evaluator. Their four-role rectangle is a test geometry, not a
claim to be a physical MOS glyph. It uses the existing orientation convention
`rot=1: (x,y) → (-y,x)` and preserves ordered D/G/S/B nodes.

|---|---|
| Four contacts at origin (100,80), no turn | D=(120,80), G=(100,60), S=(80,80), B=(100,100); box [80,60]–[120,100]. |
| Same class and origin, one quarter turn | D=(100,100), G=(120,80), S=(100,60), B=(80,80). The old contacts fail despite the unchanged square box. |
| Only B.hidden becomes true | Same four electrical nodes, contacts and box; B stops ordinary routing. The B glyph lead is retained. |
| B contact/lead extends from y=20 to y=40 | Box grows to y=120 in this pose. An obstacle at [98,112]–[102,116] rejects the new arrangement although the old box was clear. |
| One complete two-child proposal has a colliding second child | Children at (100,80) and (160,80) have distinct raw nets and no touching contacts. The obstacle touches only the second child. Decline both moves and preserve the previous reservation set. |
| A whole accepted two-child owner translates by (40,-20) | Origins become (140,60) and (200,60), retaining relative displacement (60,0). Both complete contact lists and reservations translate; reusing either old B contact fails. Ordered bindings do not change. |
| Visible B requested from a three-contact class | Decline missing required capability. Do not turn the device origin into a visible lead or infer caller-hidden authority. |
| Existing MOS cohort plus unrelated missing nine-port family | MOS collection/prototype remains eligible under its own required capabilities. A candidate actually requiring that nine-port family declines until complete. |
| Caller-fixed child contradicts the proposed relative arrangement | Decline the automatic owner; retain the admitted caller pose. Source similarity cannot override it. |

Extend the production fixture set with the sixth-study actual same-class
visible/hidden controls, shared-definition per-instance variants and the
sixth-group complete-axis controls. Use an explicit native/plugin class and
policy transport fixture when that boundary changes. The independent final
oracle must read the exported ordered pins and actual selected class/pose;
the proposal's own cached frame is not a second oracle.

## Data and ownership questions before implementation

Raw ordered electrical pins and all ownership incidences are immutable
inputs. Existing typed ClassId/device/pin/net handles identify records; a new
hot per-net “hidden” flag is unnecessary. Local contract storage belongs to
the library; occurrence requests and attachment/label requirements are cold
rows bounded by affected pins, candidates and member references. The local
arrangement owner alone writes accepted poses. F borrows those rows and
produces bounded scratch, rather than retaining a second authoritative
coordinate table. Recompute cheap derived frames at each coordinate boundary
unless measured need establishes a cache and its complete invalidation key.

Three likely changes have contained owners: a new body representation
changes C and its capability proof; a new local arrangement changes G's
bounded alternatives; another exporter consumes the committed contract and
actual frame without rerunning topology or choosing presentation itself.
None licenses a generic runtime rule language. Production storage widths,
capacity assertions, allocation failures and final host round trips remain
implementation gates, not results established by this document.

## Reviewed evidence and historical correction

This review reread `library.Terminal`, `Class.shows/side/bbox/box`,
`sketch.drawValid/wireUp`, and `Placed.Builder.run/device`, plus the current
packages, planning and sixth-group documents. The ninth provenance file
records their exact bytes before parent edits. No production code or parent
document changed here, and no compiler, host or frozen CLI was run for this
planning round.

The earlier [body-to-plan review](cross-review-bodies-to-plan.md) called the
added F dependency acyclic while treating a moved proposal as needing a new
frame. This ninth review makes that necessary qualification explicit: the
dependency is acyclic for local capabilities and evaluated candidate frames;
the phrase “complete final world frame before arranging” is too strong.
The historical review is preserved rather than silently rewritten.

The ports review also found two ambiguities in the initial prospective
fixtures: the proposed children accidentally touched at an unspecified net,
and the whole-owner example listed only one frame. The retained current
literals separate the children, declare distinct per-child nodes, and list
both translated frames and their preserved relative relation. These are
repaired planned fixtures, not evidence of a production routing bug.
