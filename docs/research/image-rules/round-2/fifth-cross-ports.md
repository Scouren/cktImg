# Fifth cross-review: actual final pins, local ambiguity and plugin identity

The fourth ports study survives independent review after two research-oracle
repairs. The review checks all **29 exact frozen-run names and 61 complete X
calls** against the saved native JSON, with an independently written inverse
rotation matrix. It actually reopens 13 fixture rasters. The executable
[probe](fifth-cross-ports-probe.py) and [result](fifth-cross-ports-probe.json)
bind all reviewed files and those fresh views by hash. No compiler, engine
change, plugin import or Schemify round trip ran in this review. These
synthetic views are additional evidence, not additions to the completed
734-pair corpus ledger or to a real-corpus selector census.

## Two failures found and repaired

The initial policy oracle read `canonical_pins` without requiring that it
describe the actual exported pin coordinates. Starting from
`shared-custom-reg`, swapping only the actual XREG INN/INP `xy` values let
the wrong drawing pass while the cached frame stayed unchanged. Ordered
formal names and net bindings still matched. This was a proof gap; the
unmodified saved native result was correct.

The repaired helper first inverse-transforms `final_device.pins` and requires
equality with the cached frame. The same mutation now fails. A second mutant
copies the positive-above policy onto XSAMPLE and updates both its actual
coordinates and cached frame. It also fails, showing that the repair does
not reduce the signed-policy test to cache consistency. The probe retains
the isolated old checker body to reproduce the failure. The complete old
script was not snapshotted before its owner repaired it; the result does not
pretend to bind that unavailable whole-file revision.

The initial bias admission helper separately used `len(pairs) == 1 and not
fixed`, where `fixed` contained every fixed device in the drawing. A unique
XAMP/XBA pair plus unrelated fixed RX therefore lost admission. The required
scope is the pair's anchor and peer. The owner materialized both an unrelated
RX and a fixed-anchor control through the frozen CLI, then repaired the
research decision. The independent replay requires these exact results:

| Literal | Complete raw peer set | Automatic relation expected | Observed XBA origin/turn |
|---|---|---|---|
| One private peer | XBA | Retain the pair | (100,200), r90 |
| Same peer, RX strongly fixed | XBA | Retain the pair; RX is unrelated | (100,200), r90 |
| Same peer, XAMP strongly fixed | XBA | Decline this pair | (290,60), r0 |
| Two private peers, XBB strongly fixed | XBA, XBB | Decline ambiguous anchor | (290,60), r0 |

The last two declines have different reasons. Counting candidates after
discarding fixed XBB invents uniqueness. Treating any fixed card as a global
veto instead loses the RX positive. Two disjoint regulator tuples are another
scope: they have different anchors and disjoint owned cards, so neither is a
raw alternative to the other. Compatibility still requires their complete
interfaces and caller relations; disjoint device sets alone are not a
general admission proof.

These findings refine P06/P17/P24/P25/P27 in the proposed rules and the
collection, instance-variant and final-frame packages. They do not change
the exact 39/36 existing-contract or 40/36 extended-contract corpus sets.

## What the plugin actually preserves

The actual enum is `Origin { core, sub, leaf, lib }`; there is no `.blk`.
The conventional-glyph field is `Symbols.shape`. The electrical family of a
subcircuit remains `.box`. Those distinctions matter to the plan:

| Boundary | Identity and geometry available there | Consequence |
|---|---|---|
| `recognize.boxPins` | Original `deck.cell_name`, every formal, explicit side information and PININFO directions | A verified generated shape can be chosen before the original name is replaced. Conflicting directions or explicit sides can instead preserve a box. |
| `Origin.sub` symbol row | Original stem, shape, complete ordered pin names and geometry | This is generated metadata; `.sub` by itself does not prove that automatic shape changes may override sides or directions. |
| `Origin.lib` symbol row | Caller library/stem, ordered caller pins and body; shape remains `.box` | Existing caller geometry has separate authority even though the engine receives a registered class in either case. |
| `layout.library` | Class `b<s>`, original ordered terminal names/positions, drawing operations | `Class` carries name, role, terminals and drawing; this registration call supplies no original definition family or generated-versus-caller provenance. |
| `layout.cellDeck` | Calls retain ordered nets, but the callee becomes `b<s>` | Recognized non-box shapes preserve named definition formals; box shapes, including external-library stubs, use `p1…pN`. The library terminal names are still original. |
| `engine.place` call | Generated text, registered library and default config | A selector reading the generated `def.name` cannot recover the original exact family from that string. This is a bounded statement about these arguments, not an assertion that the plugin has forgotten the original circuit. |
| `layout.translate` | Original `Parts.sym`, every original pin and net, final engine pose | It asserts every returned pin count, transformed endpoint and original net. An engine-only changed class would contradict this boundary unless the symbol variant travels with it. |
| `cellref` / `emit.cellFile` / `emit.graphics` | Original generated `.shcomp` or caller library reference; per-instance symbol selection; glyph regenerated from `shape` | Original electrical callees survive in the emitted circuit. A new signed variant must preserve that identity while carrying its selected geometry through emission. |

This confirms a specific semantic transport gap, not a universal failure of
current plugin placement. `bias_neighbors.find` uses
`block_symbols.identify(def.name, def.ports)` and exact peer family names;
those facts are unavailable under synthetic family names. In contrast,
`opamp.amplifier(def.ports)` is name-independent and can still recognize a
generated named-formal amplifier when the surrounding admission holds.
Readers of only original library terminal names and readers of generated
SPICE definition formals also receive different facts for box stubs.

The executed `shared-projected` fixture is a useful narrow countercontrol:
its registered b17 triangle preserves all five terminal roles and geometry,
and looks identical to the original fixture, but the exact-family research
collector loses both local candidates. It is a CLI projection, not execution
of `layout.cellDeck`, the plugin, or the host. The review confirms all final
frames and the raw-candidate distinction; it does not promote a zero-pixel
difference into downstream parity.

## Concrete boundary for an implementation

1. Read complete original contracts once. Preserve every formal index and
   occurrence. For a plugin call, either transport the verified role map and
   geometry authority explicitly or produce the same typed requests before
   `cellDeck` erases the family. Never infer permission from a `b` prefix,
   triangle outline, or mere registration.
2. Enumerate raw local alternatives per named anchor and protected interface
   from complete incidences. Decide competing embeddings and overlaps before
   fixed/visible/frame eligibility. Check held state only for the actual
   proposed members and explicitly documented interfaces.
3. Select an immutable generated class variant only after the corresponding
   owner is admitted. Caller family classes, instance classes, sides,
   directions and whole-symbol poses retain their documented precedence.
   A generated origin is one authority fact, not blanket permission.
4. Resolve the selected class before placement, lead escape, reservations,
   peer frame collection and compaction. Assign the existing per-device
   class handle; do not mutate a shared definition cache. Variant construction
   is fallible work before assignment, with an unchanged previous result on
   decline or failure.
5. Carry the same instance variant through plugin `Parts.sym`, pin frames and
   graphics emission while retaining the original electrical callee. A
   native-only frame change is insufficient for plugin parity.
6. Validate actual final transformed contacts, complete ordered bindings,
   glyph role marks, caller geometry and the host netlist independently.
   Cached canonical metadata must agree with actual final pins before any
   semantic order check. Apply the complete two-instance fixture to both
   front ends, including class reuse and the fixed/side/mirrored controls.

The smallest storage remains a bounded cold request list using existing
typed device/class handles, complete borrowed role/index rows and one owner
for accepted requests. The number of admitted instance requests is bounded
by candidate blocks; raw alternative/member-reference capacities need their
own input-derived bound. The research subset enumerator is not a runtime
algorithm. No new hot flags, generic rule language or public ABI extension
is justified by these literals alone.

## Review of the consolidated plan

The current proposed rules and implementation packages already keep raw
membership, ownership, signed frame, caller authority and wire capability
separate. The diagonal package correctly requires exact `nearTree` distance,
label anchors, coordinate transport and old-caller Manhattan compatibility.
The group package correctly retains global-axis semantics and rejects a
parent inferred solely from set containment. No new contradiction was found
in those boundaries. The following refinements were sent to the plan owner:

- Update P06's stale “executed fixtures are a follow-up” phrase to the actual
  29-run fourth study, retaining the automatic-policy-not-implemented scope.
- In the ownership package include the unique-peer/unrelated-fixed-RX and
  fixed-anchor literals alongside the fixed-rival ambiguity literal.
- Say explicitly that `Origin.sub` alone is not geometry authority: side or
  PININFO constraints can produce a deliberate box in that same origin.
- Link the now-executed independent diagonal probe from the old “cases to
  write” section. Its two-diagonal-ray literal produces three cardinal bits
  for two rays, and it adds exact distance, odd descending-label midpoint,
  f32 and host-range controls beyond the original seven planning literals.
